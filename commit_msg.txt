Preview detection; per-type epoch windows; event sources reach the analysis

Preview detection (new): try the current detection settings on chosen
trials before a run. Loads and filters through the same snapshot Run
Analysis takes, cuts trials with the same segment loop and event delay,
and opens the Data Inspector read-only. Trials are chosen in a dialogue
defaulting to an even spread across the session. Nothing is written.

Inspector gains read_only: markers are drawn but fixed, editing controls
are inert, and nothing is committed on close. Default False, so review is
unchanged.

Per-stimulus-type epoch windows. The epoch a response needs is a property
of the response: a cortical silent period wants several hundred
milliseconds after the pulse, an M-wave a few tens. One window for the
recording meant truncating the first or carrying an order of magnitude of
unnecessary samples through every trial of the second. Pre and Post are
now columns on tab 1a, seeded from a preference and following it while
unedited, and they set what the Inspector shows as well as what is cut.
An empty window map reproduces the previous behaviour exactly: one code
path, with the shared window as its degenerate case.

The epoch fields left tab 1c. Neither was visible-only despite the label,
both decided what was extracted, and one doubled as the Inspector's zoom;
three fields there looked like pre-stimulus settings and meant three
different things. What remains is the detectors' baseline, which genuinely
is one setting for the recording.

Windows are clamped to what a pre-epoched file contains, in the
per-channel copy as well as the file-wide one. The analysis reads the
former, so clamping only the latter left a run epoching into stitched
guard band and reporting mirror padding as recorded signal.

The results bundle already stored pre and post per group, but the add-on
context collapsed them to the first group's axis. AddonContext now carries
time_ms_by_type and time_ms_for(); the three built-in add-ons resolve the
axis inside every pass over stimulus types, including the figure pass, and
quantities derived from it -- baseline windows -- follow.

Event sources now reach the pipeline. They were read only to rebuild tab
1a, so a configured threshold changed the display while the analysis went
on reading the file's markers by name. Sources are per channel, with
copy-to-all, carried in the params snapshot, and recorded in the sidecar.

Event sources dialogue reworked: every kind previews, with a whole-file
view and a single-event view navigable by arrow keys or by typing an event
number. The default source now means every marker rather than the first
label alphabetically, which had silently narrowed the analysis.

Column and field explanations. Every column on tab 1a and every field on
tab 1c carries an information icon; hovering shows the text and clicking
pins it. The prose blocks those replace explained a handful of settings
each while occupying the space the tables needed, and sat far enough from
the fields that reading one meant holding a column name in mind. Where a
setting's meaning depends on state, the tooltip follows it.

CED Signal MATLAB exports are read (formats/signal_mat.py). Frames are
pre-epoched trials, so epoch bounds are reported for clamping and the
frame state becomes the stimulus type. Written from the file's own
structure, not from any other toolbox's source. These are MATLAB v7.3,
which scipy.io cannot open, so h5py becomes a dependency and is bundled
into the frozen builds.

The "In combined" column was removed. It selected which stimulus types
appeared on one figure and affected nothing else -- not the analysis, not
the per-type figures, not any CSV.

Fixes found while testing:
- the setup table was read only on Confirm, and confirmation was
  invalidated only when the table was rebuilt, so a row edited afterwards
  was displayed but not analysed
- the Event sources button discarded the channel assignment (destroy, not
  save), so sources were filed against a stale channel and the Spike2 path
  aborted the file load
- the load flow rebuilt tab 1a from every discovered marker after the
  dialogue had run, restoring types the analyst had excluded
- the range picker and the delay scan read markers directly, ignoring the
  configuration
- the preview loaded without sources, and cut every type to one window, so
  it offered different trials from the ones the run would use
- switching source kind carried a channel the new kind could not use
- edit traces accumulated on every field rebuild
- unreadable files surfaced a Rust UTF-8 parse error instead of a reason;
  a missing h5py reported a supported format as unreadable
- an EDF's sibling _events.tsv silently outranked its own annotations
- a trace bound in the constructor read a table that did not exist yet
