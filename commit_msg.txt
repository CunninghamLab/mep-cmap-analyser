Group results by family; add an optional trimmed trials file (1.4.3)

Results folder
--------------
One recording writes nine files per channel, so a two-channel study left
eighteen loose files in one folder. Results are now filed by output family
via the new mep_cmap/results_layout.py: trial-level/, summary/,
onset-methods/, segments/, add-ons/, report/. Filenames are unchanged and
nothing is moved; both the flat and the foldered layouts are read, so a
folder half in each state loads completely.

AddonContext gains addons_dir, created on first access; results_dir now
means the results ROOT and is read-only for add-ons. All five built-in
add-ons write to addons_dir. Stage 2's sidecar join searches the whole
results tree via find_results, and _S2_CORE_SUFFIXES is DERIVED from
results_layout.FAMILIES so a core output added later is excluded the day
it is written.

Trimmed trials file
-------------------
New mep_cmap/column_groups.py is the single source of truth for which
trial-level columns belong together: a protected set, thirteen selectable
groups, and a dependency table. A run may now also write
<prefix>_trials_selected.csv beside the full file, holding the protected
columns plus the selected groups.

_trials.csv is never affected and always carries every column. The
narrowing happens on a COPY at write time, immediately after the existing
to_csv call; LAT_COLS is neither read nor reordered, so the ~20 positional
index constants that assert their own positions keep a fixed schema behind
them.

The protected set is a complete join key (File, Channel, StimType,
Segment, Condition), so any dropped column can be recovered by merging the
trimmed file back against the full one. That is what makes dropping a
column safe, and it is why the dependency table holds exactly one edge:
carson_qr -> reference. Reference means can differ BETWEEN STIM TYPES, so
Normalised_Adjusted_PTP_QR without Reference_Type mixes denominators while
looking uniform. Everything else means the same thing on every row and
gets no edge, deliberately: pulling raw amplitude in everywhere would make
it impossible to deselect, which is the case the feature exists for.

A test asserts every column in the written frame is in exactly one group
or protected, so a metric appended to LAT_COLS without an assignment FAILS
rather than silently vanishing from every trimmed file ever written.

Two preferences, both registered in DEFAULTS (preferences.load() keeps
only `if k in DEFAULTS`, so an unregistered key appears to save and is
discarded on restart). Off by default. A single recording overrides them
through a tri-state control on tab 1c, stored top-level in the session
JSON rather than in "settings", whose keys all restore against a
hardcoded literal: absent has to mean "no override", not "force this
value". "Off here" stays distinct from "not set here", so a recording
opted out cannot opt itself back in when the preference is switched on.

Group analysis
--------------
A trials-file control (Full / Trimmed). Trimmed is REFUSED, naming the
offending sessions, when any included session lacks the file or when
sessions disagree on their selected groups; a table whose columns depend
on which participants were included is one where adding a participant
silently changes the analysable variables. Comparison is on the selection
recorded in the _trials.json sidecar, not on CSV headers, which cannot
tell "chose not to keep cSP" from "had no cSP data".

Add-on outputs, previously joined unconditionally, can now be excluded or
chosen individually. The picker is populated from what is actually beside
the scanned sessions, so third-party add-ons appear without being known to
the tool, and partial coverage is stated before it is chosen. Everything
ticked stores null rather than a list, so an add-on run later still joins.
The trial source and add-on choices are saved with the study design.

Fixed along the way: _s2_join_addon_sidecars derived its prefix only from
"_trials.csv", so a Trimmed build would have returned early and silently
joined NO add-on outputs at all.
